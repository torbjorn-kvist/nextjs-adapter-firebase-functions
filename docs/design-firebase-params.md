# Firebase Params & Secrets

## Problem

Next.js server code needs access to secret values (API keys, DB credentials) at runtime. Firebase Functions provides Cloud Secret Manager integration via `defineSecret`. The adapter must wire these together.

## Design

### 1. Adapter Options (declare at build time)

```typescript
// next.config.js
import { createFirebaseAdapter } from 'adapter-firebase-functions'

export default {
  adapterPath: require.resolve('adapter-firebase-functions'),
  // or use createFirebaseAdapter for config:
}

// firebase.adapter.ts (user creates this)
import { createFirebaseAdapter } from 'adapter-firebase-functions'

export default createFirebaseAdapter({
  secrets: ['DATABASE_URL', 'STRIPE_SECRET_KEY', 'JWT_SECRET'],
  params: {
    NEXT_PUBLIC_API_URL: { type: 'string', default: 'https://api.example.com' },
    ENABLE_ANALYTICS: { type: 'boolean', default: true },
  },
})
```

### 2. Generated `firebase-params.js`

The adapter generates this file in `functions/`:

```javascript
// functions/firebase-params.js — GENERATED by adapter-firebase-functions
// Do not edit manually.
'use strict'

const { defineSecret, defineString, defineBoolean, defineInt } = require('firebase-functions/params')

// Cloud Secret Manager secrets (sensitive values)
exports.DATABASE_URL = defineSecret('DATABASE_URL')
exports.STRIPE_SECRET_KEY = defineSecret('STRIPE_SECRET_KEY')
exports.JWT_SECRET = defineSecret('JWT_SECRET')

// Environment params (non-sensitive configuration)
exports.NEXT_PUBLIC_API_URL = defineString('NEXT_PUBLIC_API_URL', { default: 'https://api.example.com' })
exports.ENABLE_ANALYTICS = defineBoolean('ENABLE_ANALYTICS', { default: true })
```

### 3. Generated `index.js` imports secrets

```javascript
// functions/index.js — GENERATED
const { DATABASE_URL, STRIPE_SECRET_KEY, JWT_SECRET } = require('./firebase-params')

exports.nextjs = onRequest({
  secrets: [DATABASE_URL, STRIPE_SECRET_KEY, JWT_SECRET],
  // ...
}, handler)
```

### 4. Runtime access in Next.js code

When a secret is listed in `secrets: [...]`, Firebase injects it as `process.env.SECRET_NAME`. Next.js server code uses it normally:

```typescript
// app/api/data/route.ts
export async function GET() {
  const db = await connect(process.env.DATABASE_URL)  // ✓ available
  // ...
}
```

No special import needed in Next.js code. Standard `process.env` access.

## What Gets Written to Disk

```
firebase-dist/
  functions/
    firebase-params.js       ← generated, CJS, declares all secrets+params
    index.js                 ← imports from firebase-params, passes secrets to onRequest
```

## Edge Cases

- **No secrets**: if `secrets: []` or undefined, `firebase-params.js` is still generated (empty) and `secrets: []` in `onRequest`
- **Params only**: params go in `firebase-params.js` but NOT in `secrets[]` array
- **Duplicate names**: deduped before generating
- **Secret name validation**: Firebase secret names must match `[A-Z0-9_]+` — warn if invalid

## Why Separate `firebase-params.js`?

1. Clean separation of concerns — secrets/params definition isolated from request handling
2. Users can also `require('./firebase-params')` from other functions in the same codebase
3. Easier to inspect what secrets the app needs without reading the full `index.js`
4. Follows Firebase's own convention of defining params at the top level
